# Хост функций SEAF (`jsonata-seaf`)

Модуль `jsonata-seaf` даёт выражениям портала SEAF функции ядра и функции манифеста поверх `jsonata-core`. Хост — сервис, backend ядра или плагин IDE — реализует `SeafHost` и создаёт `SeafEnvironment` на версию манифеста. API нестабилен до `jsonata-host` (фаза 9).

## Окружение

```kotlin
val env = SeafEnvironment.create(host)                 // лимиты SeafLimits.TEMPORARY
val expr = env.compile("\$lookup(components, \$self.id)")
val result = env.evaluate(expr, input, self = selfValue, params = paramsValue, request = SeafRequest(mapOf("user" to "u1")))
```

- **Ключ окружения** — версия манифеста, в режиме ролей v1 ещё и роль. Права в ключ не входят: семантика вычисления от них не зависит, они приходят в `SeafRequest` на каждое вычисление.
- `registry` — stdlib, функции ядра и функции манифеста, заморожен. Окружение неизменяемо и общее для потоков.
- `$self` и `$params` — привязки верхнего уровня выражения. Внутрь функций манифеста они не передаются, как в ядре.
- `evaluate` по умолчанию берёт `limits.options()`. Хост может передать свои `EvaluationOptions` (слушатель отладчика, токен отмены); запрос добавляется к ним сам (`EvaluationOptions.attributes`, ключ `SeafEnvironment.REQUEST`).

## Контракт `SeafHost`

| Метод | Функция | Что требуется от хоста |
|---|---|---|
| `loadSource(manifest, source, request, context)` | `$parsesource` | единственный ввод-вывод выражения, правила ниже |
| `manifestSchema()` | `$manifestschema` | JSON Schema манифеста; спрашивается лениво |
| `versions()` | `$versions` | версии частей портала |
| `log(content, tag)` | `$log` | запись в журнал хоста в порядке ядра, `tag` — null без метки; выражению значения не возвращает; выключение — настройка хоста |

Общее для всех методов:

- Вызов идёт на потоке вычисления. Это может быть поток сегмента стека движка, поэтому `ThreadLocal` хоста там не видны: всё нужное хост берёт из `SeafRequest` и своих полей.
- Блокирующий вызов допустим. Отмена вычисления приходит прерыванием потока; хост не глотает `InterruptedException`.
- Исключение хоста движок не подменяет: оно доходит до вызывающего тем же объектом, место в выражении приходит через `EvaluationOptions.hostErrors`. Внутри `$tryexecute` оно перехватывается (`success: false`, `error` — `message` исключения).

### `loadSource`

- Разрешены только источники относительно озера или из списка протоколов и хостов конфигурации хоста. Остальное — исключение хоста.
- Таймаут загрузки не дольше `context.remainingNanos()` (остаток дедлайна вычисления, `Long.MAX_VALUE` без дедлайна).
- Размер ответа ограничивает конфигурация хоста (`maxSourceBytes`). Движок память не считает (`docs/limits.md`).
- Права пользователя проверяет хост по `request`.
- Внутри функции манифеста `manifest` — вход этой функции, а не манифест: так делает ядро (`this.manifest = context`). Поведение повторяем; кандидат на исправление описан в `docs/seaf-functions.md`.

## Средства движка для функций хоста (`CallContext`)

- `local(key) { init }` — состояние на одно вычисление (хранилище `$set`/`$get`, кэш скомпилированных схем `$jsonschema`). Вложенные вычисления видят то же состояние, другое вычисление — своё.
- `attribute(name)` — значение, которое хост приложил к вычислению (`EvaluationOptions.attributes`), например `SeafRequest`.
- `evaluate(expression, input, bindings, frameName)` — вложенное вычисление в том же контексте: глубина, дедлайн, бюджеты, отмена, слушатель отладчика и `local` общие. Переменные — только `bindings`, `$` и `$$` — `input`. Отладчик показывает кадр `frameName` (у функции манифеста — её id). Выражение компилируется с реестром той же цепочки, что у вычисления (обычно `SeafEnvironment.registry`), иначе `IllegalArgumentException`.
- `cancellation`, `remainingNanos()` — отмена и остаток дедлайна для долгих и блокирующих вызовов; `checkpoint()` — проверка отмены и дедлайна в долгом цикле (`X0009`/`D1012`).
