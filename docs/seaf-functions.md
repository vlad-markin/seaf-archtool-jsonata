# Функции ядра SEAF в движке (`jsonata-seaf`)

Поведение функций, которые ядро seaf-archtool-core регистрирует в своём драйвере JSONata, описано здесь своими словами (решение К1: код ядра в репозиторий не копируется). Эталон — драйвер ядра на коммите из `compat/seaf/core-ref.json`; эталонные значения на синтетических входах снимает шаг 3.0 (`compat/seaf/expected.jsonl`), сверяет `CoreFunctionsTest`. Пока эталонов нет, ниже помечено, что сверено и с чем.

Подключение и контракт хоста — `docs/seaf-host.md`. Каталог (CAP-8) берёт описания из `core-docs_ru.properties`.

## Состояние

| Функция | Есть | Сверено с ядром | Что нужно |
|---|---|---|---|
| `$lookup` | да | по описанию спеки и дизайна | эталоны 3.0 |
| `$tryexecute` | да | по таблице дизайна §2.3; тексты проверок аргументов — свои | эталоны 3.0 (тексты ядра) |
| `$jsonschema` | да | проверка — конформанс с ajv 8.20.0 (`SchemaConformanceTest`); формат ошибки без `attrInfo` | эталоны 3.0 или код (`attrInfo`) |
| `$set`, `$get` | да | хранилище на одно вычисление — решение B8 (DEV-15) | — |
| `$log` | да | `(content, tag)` и без результата, как в ядре (RV3-17) | эталоны 3.0 |
| `$parsesource` | да | через `SeafHost.loadSource` | — |
| `$manifestschema`, `$versions` | да | значения хоста | — |
| `$self`, `$params` | да (привязки) | `SeafEnvironment.evaluate` | — |
| `$wcard`, `$mergedeep`, `$sourcetype` | **нет** | — | код ядра или эталоны 3.0: алгоритмы не описаны ни в спеке, ни в дизайне |

Выражение с `$wcard`, `$mergedeep` или `$sourcetype` сейчас падает с `T1006` («Attempted to invoke a non-function»): это видно сразу, а не тихой разницей результата. В корпусе SEAF: `$wcard` 15 вхождений, `$mergedeep` 7, `$sourcetype` 0.

## Функции

### `$lookup(object, key)` / `$lookup(key)`

Заменяет стандартную `$lookup` (регистрация с `overridesStandard`, конфликт виден в `FunctionRegistry.conflicts()`).

- Ключ `null` даёт `null`. Стандартная функция 2.2.2 на таком ключе падает с `T0410`.
- С одним аргументом объект берётся из контекста (`$`); форма с одним аргументом — только для ключа-строки и `null`, другое значение даёт `undefined` (`$lookup(5)` при входе `{"5": "x"}` → `undefined`).
- Массив: значения ключа у всех элементов собираются в обычный массив (не последовательность: одно значение остаётся массивом, без значений — `[]`), массивы-значения разворачиваются (ревью RV3-18).
- Ключ-число или логическое значение становятся строкой, как имя свойства в JS (`$lookup({"1": 2}, 1)` → `2`). Структурированный ключ даёт `undefined`. *Не сверено.*

```
$lookup({"a": 1}, null)                     → null
$lookup("k")              вход {"k": 1}     → 1
$lookup([{"a": 1}, {"a": [2, 3]}], "a")     → [1, 2, 3]
$lookup([{"a": 1}], "a")                    → [1]
$lookup([{"b": 1}], "a")                    → []
```

### `$tryexecute(function, args)`

Вызывает функцию с аргументами массивом (нет второго аргумента — без аргументов, `null` передаётся как есть; другое значение, не массив — `success: false`, как в ядре, ревью RV3-16) и возвращает `{"success": true, "result": …}` (без `result`, если результат `undefined`) или `{"success": false, "result": null, "error": "<текст>"}`.

Что перехватывается и что нет (дизайн §2.3, CAP-13 п. 8: выражение не может перехватить свои лимиты):

| Перехватывается → `success: false` | Уходит вызывающему |
|---|---|
| ошибки `S…`, `T…`, `D…` эталона, включая `D2014` | `D1011` (глубина), `D1012` (дедлайн), `D2015` (лимит последовательности) |
| ошибки функций SEAF (`X0012`, `X0013`, коды функций манифеста) и regex (`X0003`) | `X0009` (отмена), `X0010` (бюджет), `X0005` (сегменты стека), `X0002`, `X0008` (ошибка движка), `X0011` |
| исключения функций хоста (`RuntimeException`) | `Error` JVM |

Текст `error`: для ошибки JSONata — её сообщение с подстановками, для исключения хоста — его `message`, иначе `Unknown error`. В ядре лимитов нет, поэтому на выражениях, не дошедших до лимита, результат как в ядре. Первый аргумент не функция — `success: false` с текстом `$tryexecute expects a function as its first argument`, второй не массив — `$tryexecute expects an array of arguments as its second argument` (тексты свои; тексты ядра сверяются локально).

### `$jsonschema(schema)(value)`

Возвращает функцию: `true`, если значение проходит схему, иначе массив ошибок в форме ajv — `instancePath`, `schemaPath`, `keyword`, `params`, `message`; у `enum` допустимые значения — в `params.allowedValues`, как в ядре. Ошибки с `keyword: "if"` отбрасываются, как в ядре.

- Схема компилируется как ajv ядра: draft-07, `allErrors`, строгий режим, `unicodeRegExp: false` (`pattern` — regex JS без флага `u`), форматы ajv-formats 2.1.1 и их ключевые слова (`formatMinimum` и др.), ключевое слово `$rels`. Адаптер — networknt 3.0.8, тексты `message` — его (DEV-14).
- Ошибка схемы (то, на чём ajv бросает при компиляции) — `X0012` с текстом причины.
- Скомпилированная схема кэшируется на вычисление по идентичности значения схемы.
- Значение глубже 1000 уровней — `X0013` (`docs/limits.md`).
- *Не сделано:* поле `attrInfo` ошибок ядра — формат не описан.

### `$set(key, value)`, `$get(key)`

Хранилище на **одно вычисление** (решение B8 спеки): `$set` возвращает записанное значение, `$get` — записанное в этом же вычислении или `undefined`. Следующее вычисление того же выражения и параллельные вычисления его не видят; функции манифеста внутри вычисления видят то же хранилище. В ядре хранилище живёт на объекте запроса и переживает повторные вычисления — это отличие от ядра (DEV-15). В корпусе 0 вызовов.

### `$log(content, tag)` / `$log(content)`

Передаёт значение и необязательную метку в `SeafHost.log(content, tag)`, в порядке ядра; значения не возвращает (`undefined`), поэтому `{"r": $log("x")}` даёт `{}` (ревью RV3-17). Выключение журнала — настройка хоста.

Переопределение на одно вычисление, как функция-параметр в ядре (ревью RV3-19): хост регистрирует свою `log` с флагом `FunctionDefinition.overridesForEvaluation` в реестре вычисления — `EvaluationOptions(functions = env.registry.extend().register(FunctionDefinition("log", null, impl, doc, overridesForEvaluation = true)).freeze())`. Она получает `(content, tag)` и подменяет `$log` только в этом вычислении, включая функции манифеста внутри него; реестр окружения и другие вычисления видят прежнюю. Так можно подменить только функцию ядра с побочным эффектом; без флага, для функции стандартной библиотеки, функции ядра без побочного эффекта или функции манифеста — `X0001`.

### `$parsesource(source)`

Единственный ввод-вывод выражения: `SeafHost.loadSource(manifest, source, request, context)`. Манифест — вход вычисления (`$$`). Внутри функции манифеста это вход функции — так делает ядро (`this.manifest = context`); поведение повторяем, хотя оно выглядит случайным: **кандидат на исправление** в ядре и движке вместе. Отмена и дедлайн приходят хосту через `context` (`docs/seaf-host.md`).

### `$manifestschema()`, `$versions()`

Значения хоста. Схема манифеста запрашивается у хоста один раз на окружение; нет схемы у хоста — `{}`, как в ядре.

### `$self`, `$params`

Привязки верхнего уровня выражения (`SeafEnvironment.evaluate(…, self, params)`). Внутрь функций манифеста не передаются, как в ядре.

## Функции манифеста (`functions`)

`SeafEnvironment.create(host, manifestFunctions)` разбирает раздел `functions` манифеста: `id → {title, params, code, result}`.

- **Конфликты.** id, совпадающий с функцией stdlib или любой из 12 функций ядра (в том числе ещё не реализованных), — ошибка загрузки `X0014` со списком всех конфликтов (CAP-7 п. 3). Детектор (шаг 3.5) выдаёт тот же список до загрузки.
- **Невызываемый id** (`a.b`) — предупреждение в `SeafEnvironment.warnings`, функция не регистрируется: в 2.2.2 `$a.b(2)` и так даёт `undefined`.
- **`code`** компилируется один раз на окружение с реестром окружения, поэтому функции вызывают друг друга и функции ядра. Синтаксическая ошибка в `code` всплывает при вызове (как в ядре), с `functionId`.
- **`params`** — список объявлений параметров. Объявление — JSON Schema параметра плюс `alias` (имя поля входа, без него — `param<N>`, N с нуля) и `required: true`. Аргумент-функция уходит в привязку `$<alias>`, остальные — в поля входа `code`. Аргументы проверяются схемой `{type: object, properties: {<имя>: <схема>}, required: [...]}`; ключевые слова `callback` и `params` значат «значение — функция». Нарушения — `X0015` с текстом ядра и списком нарушений в форме ajv (тексты `message` — networknt, DEV-14). *Формат объявления (`alias`/`required` рядом с ключевыми словами схемы, нумерация `param<N>`) выведен из спеки; сверить с эталонами 3.0.*
- **Без `params`** вход `code` — `undefined`, аргументы не передаются (как в ядре). Арность функции — число объявлений: функции высшего порядка передают столько аргументов.
- **`result`** — JSON Schema результата, нарушение — `X0016`. Ключевые слова `callback`/`params` в ней не допускаются (строгий режим: `X0017`).
- **Каждая запись раздела — функция**, как в ядре: без строкового `code` она возвращает `undefined`, а её id участвует в проверке конфликтов (`X0014`) наравне с остальными; `params` не массивом — `X0017` при вызове (ревью RV3-36).
- Схемы `params`/`result` компилируются при первом вызове, как в ядре, со строгим режимом ajv 8 и `pattern` с флагом `u`; ошибка схемы — `X0017` (при каждом вызове).
- **Вычисление `code`** — вложенное (`CallContext.evaluate`): глубина, дедлайн, бюджеты, отмена, отладчик и хранилище `$set`/`$get` общие с вызывающим выражением. `$self`/`$params` внешнего вычисления не видны, `$$` — вход функции, поэтому `$parsesource` внутри функции получает манифестом её вход (как в ядре). Корень берётся лексически (ревью RV3-39): лямбда внешнего выражения, вызванная внутри функции, отдаёт `$parsesource` внешний вход, а лямбда, созданная в функции и вызванная снаружи, — вход функции.
- **Рекурсия.** Функция, вызывающая себя 100 000 раз, при `SeafLimits.TEMPORARY` даёт результат; бесконечная — `D1011`, в том числе под `$tryexecute`.
- **Ошибки внутри `code`** несут `functionId`, позицию в тексте `code` (DEV-16) и кадры стека; отладчик получает источник `manifest:functions/<id>` (вид `MANIFEST_FUNCTION`) и кадр с именем id.

## Проверка без загрузки

`SeafDetector` и `jsonata-tools detect [--functions functions.json] <выражения>` находят заранее: конфликты имён (`X0014`), схемы, которые упадут при первом вызове (`X0017`), вызовы `$set`/`$get` (DEV-15), `$jsonschema` и функции манифеста со схемами (DEV-14), нарушения `$jsonschema`, взятые по номеру (`[0]` — порядок, DEV-14), вызовы функций ядра, которых в движке ещё нет. Сборка `jsonata-tools` — из исходников (`./gradlew :jsonata-tools:installDist`).
