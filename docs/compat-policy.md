# Политика совместимости с jsonata-js 2.2.2

Порядок, по которому расхождение движка с эталоном классифицируют, предлагают, согласуют, документируют и проверяют (CAP-1, CAP-2, CAP-3 спеки `docs/plan/SPEC.md`). Решения 12, 13 и 17 в `docs/context.md` — основание; эта страница — порядок работы.

**Эталон** — jsonata-js 2.2.2, коммит 6c7e95f: код (`compat/jsonata-js/src`), test-suite и `errorCodes`, пакет `jsonata@2.2.2` в `compat/node`. Документация docs.jsonata.org эталоном не является. Если эталон и чьё-то понимание JSONata расходятся, прав эталон.

## Виды расхождений

| Вид | Что делаем | Где записано |
|---|---|---|
| **Ошибка движка** | Чиним до коммита. Регрессионный тест, при необходимости ловушка в `compat/traps` | Тест; ловушка |
| **Согласованное отличие** | Только по решению владельца (ИТ-лида). Встроено всегда, переключателя нет (решение 17) | `docs/deviations.md`, тест, проба или статическое правило детектора |
| **Нестабильность эталона** | Не отличие. Тест проверяет свойства (тип, диапазон, монотонность в пределах вычисления), а не значения | `docs/deviations.md`, раздел «Нестабильность эталона» |

Нестабильности эталона: `$now()`, `$millis()` (текущее время), `$random()`, `$shuffle` (случайный порядок), позиция и имя ошибки, оставшиеся на общем объекте встроенной функции от прошлого вызова, текст ошибок JS там, где эталон падает исключением JS (`TypeError`, `RangeError`, `SyntaxError`).

## Жизненный цикл отличия

1. **Кандидат.** Запись `P-NN` в `docs/proposals.md` со всеми полями (ниже) и статусом «предложено». До решения движок держит поведение эталона, и тест закрепляет именно его.
2. **Решение владельца.** Статус меняется на «принято <дата> → DEV-NN» или «отклонено <дата>: причина». Отклонённое предложение остаётся в `proposals.md`, поведение — как у эталона.
3. **Запись.** `DEV-NN` в `docs/deviations.md` со всеми полями (ниже) и реализация. В одном коммите: код, тест, проба или статическое правило (`su.seaf.archtool.jsonata.deviation`), строки `compat/pass/deviations.txt`, если затронуты случаи test-suite, разрешения в `TrapsTest`, если затронуты ловушки.
4. **Проверка.** Гейты (ниже) зелёные. Расхождение объясняется отличием, только если на этом вычислении сработала его проба; статическое правило показывает «может затронуть».

Случай уходит из храповика test-suite только вместе с записью `DEV-NN` и её id в сообщении коммита.

### Поля предложения `P-NN`

Предложение без любого из полей не рассматривается и возвращается автору.

- **id** `P-NN` — следующий свободный номер.
- **Категория** — id из каталога расхождений отчёта jsonata-java (`ORD-01`, `STR-03`, `UND-03`…) или новый с префиксом `ORD-`, `STR-`, `NUM-`, `DT-`, `RE-`, `ERR-`, `PERF-`, `DBG-`…
- **Статус** — предложено / принято (дата, кем, → DEV-NN) / отклонено (дата, причина) / наблюдение (не отличие).
- **Суть.**
- **Пример:** минимальное выражение и вход, результат jsonata-js 2.2.2, результат движка.
- **Мотив:** производительность / отладка / ошибка эталона.
- **Замер** — обязателен для мотива «производительность»: методика стенда (CAP-14, `docs/perf-method.md` после шага 6.2), медиана и p95 до и после, аллокации.
- **Охват:** число выражений корпуса SEAF и вычислений на озёрах, где меняется результат (локальные гейты).
- **Миграция:** детектор, автопереписывание или ничего.
- **Меняет ли результат** выражений.

Порога «заметного выигрыша» нет: владелец решает по замеру и охвату. Ориентир для автора: не меньше 20 % медианы времени или памяти на запросе стенда или озера, либо снятие квадратичности или падения по памяти, либо возможность отладки, недоступная иначе.

### Поля записи `DEV-NN`

- **id** `DEV-NN` — **следующий свободный** номер в момент коммита; номера не переиспользуются, в задании заранее не фиксируются. Так же нумеруются коды движка `X` (`parser/Errors.kt`).
- **Категория** (как у предложения).
- **Пример** «2.2.2 → движок» (выражение, вход, оба результата).
- **Причина.**
- **Решение:** кто, дата, источник (решение в `docs/context.md`, ревью, протокол).
- **Версия движка**, с которой отличие действует.
- **Меняет результат** — да / нет / только где эталон падает исключением JS.
- **Тест** — имя теста.
- **Правило детектора** — статическое правило по AST и/или проба (ветка кода, где движок поступает иначе, чем эталон).
- **Случаи test-suite и ловушки**, которые оно затрагивает.

## Ошибки эталона

Ошибку самого jsonata-js (DT-05/DT-06 — пояс `-0530`, STR-03 — `$base64encode` в Latin-1, RE-07, UND-03) движок исправляет как согласованное отличие, если гейты корпуса и озёр не нашли затронутых выражений. Каждое исправление — отдельная запись. Если затронутые выражения есть, движок повторяет поведение эталона, пока владелец не решит иначе. Уже исправлены: STR-03 (DEV-11).

Исправление jsonata-js после 2.2.2, которое меняет результат, переносится только как отличие по этой политике (диалект заморожен, решение 13).

## Отличия и флаг инсталляции

Внутри движка согласованные отличия включены всегда, собственного флага у движка нет (решение 17). Инструмент переходит на движок целиком по флагу инсталляции (CAP-16): выключен — всё считает jsonata-js, отличий нет; включён — jsonata-js не используется нигде. Смешанного режима нет.

### Контрольный список релиза

1. Храповик зелёный, `compat/pass/*.txt` не уменьшился без записи DEV.
2. `docs/deviations.md`, `compat/pass/deviations.txt`, страница отличий для пользователей (шаг 1.10) и `CHANGELOG.md` согласованы. Отличие, меняющее результат, выходит не меньше чем в minor-версии (semver; до `jsonata-host` версии 0.x, такое отличие поднимает minor) с анонсом потребителям API и CI.
3. Фаззинг: ≥ 40 000 случаев с новым seed, 0 необъяснённых.
4. Локально: корпус (100 %), озёра (0 необъяснённых), отчёт `docs/reports/compat-<дата>.md` по правилу анонимизации.
5. Дрейф ядра: эталонные значения функций ядра SEAF привязаны к коммиту ядра (`compat/seaf/core-ref.json`, история 3); если ядро ушло вперёд, сначала отдельный коммит движка с разницей `expected.jsonl`.
6. Версия эталона — `compat/jsonata-js/VERSION` = 6c7e95f (2.2.2).

## Анонимизация отчётов

Репозиторий публичный. В `docs/reports/*` и в любые коммиты не попадают: имена озёр, пути, id и тексты выражений корпуса и озёр, данные архитектур. «Худшие N» — только номер по порядку и отношение времени, без идентификаторов. Подробности по выражениям (`details.json` детектора) получает только владелец инсталляции, в репозиторий они не коммитятся.
