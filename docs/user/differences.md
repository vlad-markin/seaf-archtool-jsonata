# Отличия JVM-движка от портала на jsonata-js

Страница для архитекторов и авторов выражений SEAF ArchTool (CAP-15 п. 1). Когда в инсталляции включают JVM-движок (флаг CAP-16, `docs/user/jvm-switch.md`), выражения вычисляются им, а не jsonata-js 2.2.2. Почти все выражения дают тот же результат. Ниже — все места, где результат может отличаться, с примером и тем, что делать.

Найти такие места в своём озере заранее помогает детектор: `jsonata-tools detect` (см. `jvm-switch.md`). Он делит находки на «может затронуть» (по тексту выражения) и «подтверждено» (на вашем манифесте сработала проверка в движке).

Подробности для разработчиков — `docs/deviations.md` (те же номера).

## Отличия от jsonata-js

### DEV-01. Трансформация не меняет исходный документ

Шаблон `|…|{…}|`, который указывает на исходный документ (`$$` или переменную с ним), в jsonata-js может изменить сам манифест, и это видно дальше в том же выражении. Движок меняет только копию.

```
($r := $ ~> |$$.a|{"b":99}|; [$r, $$.a.b])      вход {"a":{"b":1}}
было: [{"a":{"b":1}}, 99]     станет: [{"a":{"b":1}}, 1]
```

Что делать: ничего — новое поведение правильное; если выражение рассчитывало на изменение входа, используйте результат трансформации.

### DEV-02. Очень глубокая рекурсия

Где jsonata-js падает с ошибкой JavaScript (`RangeError`, например римские цифры для чисел от 10 миллионов), движок сообщает ошибку `X0002` или `X0005`. Рекурсия до 100 000 уровней работает, как и раньше.

### DEV-03. Частичное применение встроенной функции проверяет аргументы

`$имя(?)` с аргументом не того типа: jsonata-js вызывает функцию без проверки, движок проверяет и приводит аргумент по сигнатуре.

```
$uppercase(?)(1)   было: ошибка JavaScript   станет: ошибка T0410
$count(?)(5)       было: undefined           станет: 1
```

Что делать: передавать аргументы нужного типа.

### DEV-04. Недопустимый в JavaScript синтаксис regex

Конструкции, которых нет в JavaScript (`a++`, `(?i)`, `(?>…)`, `\k` при именованных группах внутри `[...]`), дают ошибку `X0003` вместо ошибки JavaScript.

### DEV-05. Символы U+E000–U+E7FF в regex

Символ из этого диапазона в шаблоне или строке совпадает и с одиночным суррогатом UTF-16. В документах SEAF такие символы почти не встречаются.

### DEV-06. Регистр в regex с флагом `i`

Сравнение без учёта регистра идёт по правилам Unicode Java: `ſ` совпадает с `s`, знак Кельвина `K` — с `k`, `İ`/`ı` — с `i`/`I`, `ß` — с `ẞ`. Ссылка `\N` на группу, которая ещё не захвачена, не совпадает (в JavaScript — пустая строка).

### DEV-07. `$toMillis` без часового пояса — всегда UTC

```
$toMillis("2023-11-14T22:13:20")
было (сервер в Москве): 1699989200000   станет: 1700000000000
```

Что делать: если нужно местное время, указывайте смещение (`…+03:00`).

### DEV-08. Конструктор объекта над пустым массивом

Группировка `path{…}` над пустым массивом данных в jsonata-js дописывает в этот массив `undefined` (в JSON — `null`). Движок массив не меняет.

### DEV-09. Какая ошибка будет в сообщении, если падают несколько значений конструктора

Если в `{…}` или `[…]` ошибочны несколько значений, движок сообщает первую по порядку, jsonata-js — ту, что «раньше завершилась». Так же одна regex-переменная в нескольких значениях конструктора в jsonata-js делит состояние поиска, и результат зависит от порядка вычисления; в движке каждое значение считается независимо.

### DEV-10. Позиция ошибки внутри функции

Ошибка внутри `function(…){…}` указывает на место ошибки внутри функции, а не на её вызов. Цепочка вызовов есть в стеке ошибки.

### DEV-11. `$base64encode`/`$base64decode` в UTF-8

```
$base64encode("é")   было: "6Q=="   станет: "w6k="
```

Нелатинские символы кодируются в UTF-8, как в остальном мире; jsonata-js брал младший байт символа.

### DEV-12. `undefined` не попадает в результат пути

```
x.a[true]     вход {"x":[{"a":1},{},{}]}     было: [1,null,null]   станет: 1
[{"a":1},{"a":2}][0].a                       было: undefined       станет: 1
```

### DEV-13. Ошибки внутри `$eval`

Ошибка лимитов или движка и ошибка функции хоста внутри `$eval` приходят как есть, а не обёрнутыми в `D3121`.

### DEV-17. Имя функции в ошибке

Если встроенная функция передана значением (`x ~> $uppercase`, `$map(xs, $string)`) и падает, в ошибке всегда её имя. В jsonata-js имя и позиция зависели от того, что сервер вычислял раньше.

## Отличия от текущего ядра портала

### DEV-14. Тексты нарушений JSON Schema

`$jsonschema` и проверка параметров функций манифеста находят те же нарушения (поля `instancePath`, `keyword`, `params`), но поле `message` — на английском, текстами другого валидатора.

```
было:   "message": "must have required property 'b'"
станет: "message": "required property 'b' not found"
```

Что делать: не разбирать текст `message`, использовать `keyword` и `params`.

### DEV-15. `$set`/`$get` живут одно вычисление

Значение, записанное `$set`, видно только до конца того же вычисления (в том числе внутри функций манифеста). Раньше оно переживало повторные вычисления в рамках запроса. В корпусе SEAF вызовов нет; детектор покажет их в вашем озере.

### DEV-16. Позиция ошибки внутри функции манифеста

Ошибка в `code` функции манифеста указывает на место в тексте `code` и содержит id функции, а не позицию вызова.

### Имена функций манифеста

Функция в разделе `functions` с именем встроенной функции (`sum`, `lookup`, `wcard`…) — ошибка загрузки манифеста `X0014` со списком всех таких имён и рекомендацией переименовать. Раньше последняя регистрация молча побеждала. Детектор находит конфликты заранее.

### Функции ядра, которых пока нет

`$wcard`, `$mergedeep`, `$sourcetype` в движке ещё не реализованы: выражение с ними даёт ошибку `T1006`. До их появления флаг в инсталляции, где они используются, не включают (`docs/seaf-functions.md`).
