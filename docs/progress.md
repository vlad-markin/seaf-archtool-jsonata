## Ускорение (после фазы 8, без изменения поведения)

Профиль JFR (`./gradlew :jsonata-compat:bench -PbenchJfr=файл`) показал главные затраты: поиск ключа в `ObjectValue` (`LinkedHashMap`, хэши строк), выделение массивов последовательностей, проверку сигнатур регуляркой на каждом вызове. Сделано:

- `ObjectValue` — параллельные массивы в порядке вставки, линейный поиск по идентичности строки (имена в путях интернируются, как имена полей у Jackson), хэш-индекс от 9 ключей, порядок JS — кэшированная перестановка;
- шаг пути не копирует собранную последовательность, если раскрывать нечего; `ArrayValue` выделяет массив при первой вставке;
- сопоставление сигнатуры мемоизировано по строке символов аргументов;
- (по ревью) группировка без квадратичного копирования, один `Matcher` на строку для regex, кэш разобранных картинок дат;
- `$match`/`$replace` (замена строкой)/`$split`/`$contains` со встроенным regex обходят совпадения напрямую по `Matcher`, без объектов протокола `{match, start, end, groups, next}`; те же правила `lastIndex`, `D1004` и лимита (следующее совпадение ищется до проверки лимита). Пользовательский матчер и замена функцией идут через протокол, как раньше. Тест: `EngineTest` «library functions give the same results with and without the matcher protocol» (сравнение с тем же regex за лямбдой); фаззинг 50 000 случаев (seed 707) — 0 необъяснённых.
- `$formatNumber`: разбор и проверка картинки (D3080–D3093) кэшируются по строке картинки, если опций нет (с опциями — разбор на каждый вызов, как раньше); `JsNumber.toString`/`toFixed` для целых по модулю меньше 2^53 — без `Double.toString`/`BigDecimal` (целое — само себе кратчайшее представление); `$toMillis` читает поля даты без `toDouble` на группу. Тесты: `JsNumberTest` «integers take the fast path with the same text as JS» (ожидания из Node 22, включая `-0` и границу 2^53), `EngineTest` «cached number pictures and parsed dates give the reference results»; фаззинг 60 000 случаев (seed 808, 909) — 0 необъяснённых. Для выбора случая стенда — `-PbenchFilter=текст`.

## Сделано

### Фаза 2. Модель данных

- `su.seaf.archtool.jsonata.value`: `Value` (sealed) — `NullValue`, `BooleanValue`, `NumberValue` (double, `-0` сохраняется), `StringValue`, `ArrayValue` (флаги последовательности `isSequence`/`keepSingleton`/`tupleStream`/`outerWrapper`/`cons`), `ObjectValue`, `FunctionValue`. **undefined — это Kotlin `null`**, а не значение; JSON `null` — `NullValue`.
- Порядок ключей `ObjectValue` — как у объекта JS (ловушка ORD-01, правило CLAUDE.md): сначала ключи-индексы (`0`…`2^32-2`) по возрастанию, затем остальные в порядке вставки; перезапись ключа сохраняет его место.
- `JsNumber`: `Number.prototype.toString` (на основе кратчайшего представления JDK 19+ с поправкой для субнормальных, где JDK берёт 2 цифры: `4.9E-324` → `5e-324`), `toPrecision`, `toFixed`, `toString(radix)`. Сверено с V8 на 6000 случайных double (`js-numbers.txt`, сгенерирован Node 22).
- `JsonWriter`: `JSON.stringify` (экранирование как в JS, включая одиночные суррогаты, отступы) и режим `$string` (15 значащих цифр, функции → `""`, D1001 на бесконечности внутри структуры).
- `jsonata-json`: `JsonataJson.parse/stringify/write` на Jackson streaming без дерева и без рекурсии (вложенность ограничена только памятью), числа — double с корректным округлением, дубликаты ключей — как `JSON.parse`. Все датасеты test-suite читаются и пишутся обратно эквивалентно.

### Фаза 4. Вычислитель v0

- `su.seaf.archtool.jsonata.engine`: AST компилируется один раз в дерево узлов (класс на тип узла, у каждого — AST и позиция), вычисление — виртуальный вызов `eval`. Общая обёртка `Node.evaluate` повторяет `evaluate` эталона: единая точка `EvalContext.enter()` (глубина + `checkpoint()`; без лимитов — инкремент и проверка поля), предикаты, группировка, схлопывание последовательностей.
- Отладка (решение 15): флаг `CompileOptions(debug = true)` оборачивает каждый узел в `DebugNode` с хуком «вход/выход/ошибка»; без флага в дереве нет ни одного вызова хука. Фреймы вызова лямбд хранят узел вызова и вызывающий фрейм — стек вызовов JSONata восстанавливается.
- Функции: `Lambda` (замыкание), `NativeFunction`, частичное применение, функции-матчеры regex, трансформер; `apply` с трамплином для хвостовых вызовов (`thunk` из парсера) — хвостовая рекурсия на 200 000 уровней не растит стек JVM.
- Реестр функций (решения 6, 14, 18): публичный `FunctionRegistry` — цепочка stdlib → свои функции, регистрация с сигнатурой JSONata и арностью; повторное имя — ошибка `X0001`; `FunctionRegistry.function(...)` создаёт функцию-значение (функция хоста может вернуть функцию). Нативный код получает `CallContext` (контекст, время вычисления, вызов функций-значений).
- Лимиты 2.2.2 (`stack` → D1011, `timeout` → D1012, `sequence` → D2015) — `EvaluationOptions`; `KotlinEngine` переводит `timelimit`/`depth` test-suite в `U1001`, как `timeboxExpression`.
- Регулярные выражения: транслятор синтаксиса JS → `java.util.regex` в одном месте (`.`/`\s`/`$`/`^` по правилам JS, `[^]`, Annex B: литеральные `{`, `]`, восьмеричные escape, identity escape) и протокол матчера эталона (`match/start/end/groups/next`, D1004).
- Неизменность входа (решение 8): трансформация меняет только объекты копии (`docs/deviations.md`, DEV-01).
- Модульные тесты движка (`EngineTest`): реестр, хук и стек вызовов, хвостовая рекурсия, лимиты и Ackermann из `implementation-tests.js`, `X0002` вместо падения на глубокой рекурсии, конкурентное вычисление одного выражения на 200 виртуальных потоках, матчеры, обход объектов, защита от `__proto__`.

### Фаза 5. Стандартная библиотека

- `StandardLibrary` — функции `functions.js` с сигнатурами и арностями эталона, регистрируются через тот же `FunctionRegistry`. `Encoding` — URL-функции по алгоритмам ECMA-262, base64 как `Buffer` Node в кодировке `binary`.

Повторены семантика `Date.UTC` (годы 0–99 → 19xx, усечение миллисекунд), `Date.parse` V8 для ISO-строк, арифметика смещений эталона (`-0530` → −6:30, DT-05; `[Z]` при разборе, DT-06), JS-истинность компонентов при выборе комбинации дата/время. Разобранные картинки кешируются.
- `NumberFormatting` — `$formatNumber` (картинка F&O 4.7, D3080–D3093, округление эталона через `$round` и `toFixed`).
- Регулярные выражения: эмуляция кодовых единиц UTF-16 (ловушка RE-07), отказ на синтаксисе, недопустимом в JS (`X0003`, DEV-04), лимит `sequence` проверяется на всех последовательностях, как `createSequence` эталона.
- Ловушки (`compat/traps`, README там): 398 случаев из `divergences.jsonl` и `targeted.jsonl` оценки dashjoin, ожидания заново сняты с `jsonata@2.2.2` скриптом `compat/node/traps.mjs`; `TrapsTest` сравнивает текст JSON (с порядком ключей) и коды ошибок.

### Задел для отладчика (сверка с прототипом `claude/debug-api`, `debugger-api.md` §A.12)

| Требование SPI | Состояние |
|---|---|
| хук `enter/exit/error` из единственной точки вычисления узла | есть: `DebugHook`, `DebugNode`, только при `CompileOptions(debug = true)` |
| хук на вычисление, не глобальный | есть: `EvalContext.hook` |
| `node.type`, дети, позиция | тип и конец токена (`position`) — да; **начала узла (`start`) нет** |
| `env.parent`, `localBindings`, базовый кадр | есть: `Frame.parent`, `Frame.localBindings()`, `Frame.ctx` |
| стек вызовов | есть: `Frame.callSite` + `Frame.caller` у кадров лямбд |
| тело лямбды и thunk хвостового вызова | есть: `Lambda.body`, `Lambda.thunk` (трамплин в `Evaluator.apply`) |

Пробел: диапазон `[start, end)` у узлов. В AST эталона есть только `position`, поэтому начало надо собирать в парсере рядом с AST (не в самом `ast()`, чтобы не сломать сверку со снапшотами) — задача спеки отладчика. Хук пока внутренний (`internal`), публичным станет вместе со спекой.
