# Кандидаты в отличия от jsonata-js 2.2.2

Решение 12: компромисс ради скорости или отладки возможен только с согласия владельца. Здесь — кандидаты с примером и ценой; до согласования движок ведёт себя как эталон. Согласованное отличие переносится в `docs/deviations.md`.

## P-01. Позиция ошибки внутри лямбды

**Что:** jsonata-js записывает позицию и имя последнего вызова на объект лямбды и затирает ими позицию любой ошибки, всплывшей из её тела. В итоге ошибка указывает на место вызова, а не на оператор, который её вызвал.

```
($f := function(){ 1 + "a" }; $f())
jsonata-js 2.2.2: T2002, position 33 (вызов $f()), token "+"
предложение:      T2002, position 22 (оператор +), стек вызовов отдельно: $f() @33
```

**Выигрыш:** отладка: позиция указывает на реальное место ошибки, а цепочку вызовов даёт стек (он у нас восстанавливается по фреймам).
**Цена:** `position` ошибок времени выполнения внутри функций перестаёт совпадать с эталоном. Test-suite позиции eval-ошибок не проверяет; затронет UI, где по позиции подсвечивают выражение.
**Замер:** не нужен (на скорость не влияет).

## P-02. `$base64encode`/`$base64decode` в UTF-8

**Что:** эталон (Node `Buffer` в кодировке `binary`) обрезает каждый символ до младшего байта, поэтому не-латинские строки портятся (ловушка STR-03 из отчёта по dashjoin).

```
$base64encode("Привет")
jsonata-js 2.2.2: "H0A4MjVC"  (байты 1F 40 38 32 35 42 — мусор)
предложение:      "0J/RgNC40LLQtdGC" (UTF-8)
```

**Выигрыш:** корректные данные. **Цена:** отличается результат для символов выше U+00FF; для ASCII/Latin-1 совпадает. Нужно знать, есть ли в выражениях SEAF `$base64*` с не-ASCII.

## P-03. `undefined` внутри последовательностей

**Что:** фильтр, который пропускает отсутствующее значение, оставляет в результате пути `undefined`, и в JSON это превращается в `null`:

```
x.a[true]      вход {"x":[{"a":1},{"b":2},{"c":3}]}
jsonata-js 2.2.2: [1, null, null]
предложение:      1
```

Так же `[{"a":1},{"a":2}][0].a` у эталона даёт undefined (предикат шага-конструктора схлопывает массив до объекта, и следующий шаг его не обходит), хотя ожидается `1`.

**Выигрыш:** предсказуемость; во внутренних последовательностях не нужно поддерживать `undefined` (немного проще и быстрее модель). **Цена:** расходится результат этих краевых выражений; в test-suite таких случаев нет.

## P-04. Производительность: проверка сигнатур нативных функций

Пока только наблюдение для фазы 9: проверка сигнатуры строит строку символов аргументов и прогоняет regex на каждом вызове, как эталон (по отчёту dashjoin это 35–57% CPU на простых путях у порта). Ускорить можно без изменения поведения (предкомпилированный автомат по символам). Отличием от эталона не станет — записано, чтобы не потерять.
