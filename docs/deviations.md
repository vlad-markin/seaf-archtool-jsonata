# Отличия от jsonata-js 2.2.2

Осознанные отличия движка от эталона (решение 17 в `docs/context.md`): они встроены всегда, переключателя нет. Гейт test-suite — `eval` 1686/1686 за вычетом id случаев, перечисленных здесь (`compat/pass/deviations.txt`). Сейчас ни одно отличие не затрагивает случаи test-suite.

Порядок записи, поля и нумерация — `docs/compat-policy.md`. У каждой записи: категория (каталог расхождений отчёта jsonata-java или своя метка), причина, решение с датой и источником, версия движка, меняет ли результат, тест и правило детектора (статическое правило и/или проба, `su.seaf.archtool.jsonata.deviation`). Номера не переиспользуются.

Кандидаты, которые ещё не согласованы, лежат в `docs/proposals.md`; до согласования поведение — как у эталона.

## DEV-01. Трансформация не меняет входной документ

- **Категория:** DATA (мутация входа).
- **Причина:** решение 8 (разобранный документ переиспользуется между вычислениями, вычисление не мутирует вход).
- **Решение:** владелец, 2026-10-11 (решение 8 `docs/context.md`).
- **Версия движка:** 0.1.0.
- **Меняет результат:** да, если шаблон трансформации указывает на исходный документ.
- **Тест:** `EngineTest` «transform never modifies the input», «transform with a user clone returning its argument leaves the input unchanged (RV-2)».
- **Правило детектора:** шаблон трансформации, который ссылается на `$$` или переменную с входом; проба — шаг 1.4.

jsonata-js меняет найденные шаблоном объекты на месте. Обычно это объекты копии из `$clone`, но шаблон может указать и на исходный документ (`$$`), и тогда эталон меняет вход. Мы применяем обновление и удаление только к объектам копии.

```
($r := $ ~> |$$.a|{"b":99}|; [$r, $$.a.b])      вход {"a":{"b":1}}
jsonata-js 2.2.2: [{"a":{"b":1}}, 99]
движок:           [{"a":{"b":1}}, 1]
```

Случаев test-suite: нет.

## DEV-02. Глубина рекурсии и `X0002`

- **Категория:** ERR (стек), PERF.
- **Причина:** решение 18 (свои коды движка с буквой `X`); решение владельца по ревью RV-4.
- **Решение:** владелец, 2026-10-25 (ревью RV-4, Р1).
- **Версия движка:** 0.1.0.
- **Меняет результат:** только там, где эталон падает исключением JS (`RangeError`), и при исчерпании бюджета сегментов (`X0005`).
- **Тест:** `EngineTest` «non-tail recursion 100 000 levels deep as jsonata-js (RV-4)», «JVM stack exhaustion is reported as X0002», «roman numerals of huge numbers fail fast as the reference does (fuzzing)»; `StackSegmentsTest`; ловушка `FZ-04#2`.
- **Правило детектора:** не нужно для результата; римские цифры чисел от 10 000 000 — проба в шаге 1.4.

jsonata-js 2.2.2 вычисляет асинхронно, и глубина рекурсии ограничена кучей, а не стеком: нехвостовая рекурсия на 100 000 уровней (`($f := function($n){ $n = 0 ? 0 : 1 + $f($n - 1) }; $f(100000))`) даёт `100000`. Движок даёт тот же результат: вычисление идёт в потоке вызывающего, а когда вложенность в текущем потоке превышает порог, продолжает на потоке с большим стеком из пула движка (сегментированный стек, `EvalContext.onNewSegment`, `SegmentPool`; устройство, память вне кучи и процессный бюджет `StackSegments.budget` — `docs/limits.md`). Обходы структур данных (`JSON.stringify`/`$string`, `=`, `**`, `$clone`, раскрытие массивов, трансформация) написаны без рекурсии. Гарантия, закреплённая тестом (`EngineTest`): 100 000 уровней нехвостовой рекурсии и рекурсии по дереву данных такой глубины, в том числе из потока со стеком 256 КБ.

Римские цифры (`$formatInteger(n, "i")`, `[YI]` и т. п.) эталон строит рекурсией по одному вызову на цифру и на числах от ~10 млн исчерпывает стек JS (`RangeError`; точная граница зависит от стека Node, на Node 22 — 9 765 661). Движок на числах от 10 000 000 сообщает `X0002`, а не пишет миллионы `m`.

Отличие остаётся только там, где стек всё-таки исчерпан (нативная функция хоста, которая рекурсивно вызывает вычислитель в обход границ сегментов): эталон в похожих местах падает исключением JS, движок сообщает `X0002`.

Цена: передача на поток сегмента — раз на 20 000 вложенных шагов вычисления (первая — после 120 в потоке вызывающего; выражение с рекурсивной лямбдой начинает сразу на сегменте); на обычных выражениях — одно сравнение на узел. Замер: та же рекурсия на 100 000 уровней — ~0,15 с у движка в прогретом JVM, ~2 с у jsonata-js; рекурсия глубиной 40 в `$map` на 20 000 элементов — ~0,2 с (эталон ~5 с). Если бюджет сегментов исчерпан, вычисление получает `X0005` (у эталона такого предела нет: это осознанный предел памяти вне кучи, `docs/limits.md`).

Случаев test-suite: нет.

## DEV-03. Частичное применение нативной функции проверяет сигнатуру

- **Категория:** PART-01.
- **Причина:** нативный код получает аргументы, уже проверенные и приведённые сигнатурой.
- **Решение:** владелец, 2026-10-25 (ревью RV-14).
- **Версия движка:** 0.1.0.
- **Меняет результат:** да.
- **Тест:** `EngineTest` «partial application of a native function checks its signature (DEV-03, RV-14)».
- **Правило детектора:** см. ниже; проба — шаг 1.4.

jsonata-js вызывает частично применённую нативную функцию в обход сигнатуры (`applyNativeFunction`), движок проверяет аргументы по её сигнатуре. Расхождение бывает двух направлений:

1. **Падение эталона → результат или ошибка JSONata.** Где jsonata-js падает с `TypeError`, движок приводит аргумент или сообщает `T0410`.

```
$sum(?)(5)          jsonata-js 2.2.2: TypeError (args.forEach is not a function)   движок: 5
$uppercase(?)(1)    jsonata-js 2.2.2: TypeError (str.toUpperCase is not a function)  движок: T0410
```

2. **Значение эталона → ошибка `T0410`** (ревью RV-14). Где нативная функция эталона без проверки молча возвращает результат на аргументе чужого типа (обычно `undefined`), движок отвергает аргумент.

```
$map($, $match(?, /^(\w*\s\w*)/)).match      вход 1, [[1,2]] или {"a":1}
jsonata-js 2.2.2: undefined
движок:           T0410 (аргумент 1 функции match не соответствует сигнатуре)
$count(?)(5)        jsonata-js 2.2.2: undefined   движок: 1
```

Правило детектора: частичное применение нативной функции (`$имя(…?…)`, в том числе переданное в функцию высшего порядка), если в позицию `?` может прийти значение не того типа, что требует сигнатура функции (число или объект вместо строки и т. п.).

Случаев test-suite: нет.

## DEV-04. Синтаксис regex, недопустимый в JS, — ошибка `X0003`

- **Категория:** RE-01.
- **Причина:** решение 18.
- **Решение:** владелец, 2026-10-25 (ревью фаз 2–5).
- **Версия движка:** 0.1.0.
- **Меняет результат:** только там, где эталон падает исключением JS (`SyntaxError`).
- **Тест:** ловушки `RE-01#4`, `RE-01#5` (`TrapsTest`).
- **Правило детектора:** статическое: литерал regex с конструкциями Java, которых нет в JS (`++`, `*+`, `?+`, `(?i)`, `(?>`); шаг 1.4.

`java.util.regex` принимает конструкции, которых нет в JS (`a++`, `(?i)`, `(?>...)`). jsonata-js на них падает с `SyntaxError` при вычислении литерала (ошибка JS без кода JSONata). Мы отвергаем такой литерал тоже при вычислении, с кодом `X0003` и позицией литерала.

```
$contains('aa', /a++/)
jsonata-js 2.2.2: SyntaxError: Invalid regular expression: /a++/g: Nothing to repeat
движок:           X0003 Invalid regular expression "a++": Nothing to repeat
```

Случаев test-suite: нет. Ловушки: `RE-01#4`, `RE-01#5` (`compat/traps`).

## DEV-05. Кодовые единицы UTF-16 в regex: ограничение эмуляции

- **Категория:** RE-07.
- **Причина:** эмуляция кодовых единиц UTF-16 в `java.util.regex`.
- **Решение:** владелец, 2026-10-25 (ревью фаз 2–5).
- **Версия движка:** 0.1.0.
- **Меняет результат:** только при символах U+E000–U+E7FF вместе с суррогатами.
- **Тест:** `EngineTest` «regex over a long string with surrogates is linear (RV-5)»; ловушки `RE-07` (`TrapsTest`).
- **Правило детектора:** статическое: литерал regex с символами U+E000–U+E7FF; шаг 1.4.

Без флага `u` JS сопоставляет кодовые единицы UTF-16, а `java.util.regex` — кодовые точки. Чтобы повторить JS (эмодзи — две единицы, `.` берёт одну, ловушка RE-07), движок отображает каждый суррогат один к одному в символы частной области U+E000–U+E7FF и в шаблоне, и в строке. Расхождение возможно, только если строка или шаблон содержат настоящие символы U+E000–U+E7FF вместе с суррогатами: например, `$contains("", /[\uD800]/)` у нас `true`, у эталона `false`.

Цена: если в строке есть суррогаты, она один раз копируется с отображением (O(n) на строку и матчер, не на совпадение).

Случаев test-suite: нет.

## DEV-06. Регистр в regex с флагом `i` и ссылка на ещё не захваченную группу

- **Категория:** RE (регистр), Р3.
- **Причина:** решение владельца по ревью RV-11 — не эмулировать.
- **Решение:** владелец, 2026-10-25 (ревью RV-11, Р3).
- **Версия движка:** 0.1.0.
- **Меняет результат:** да.
- **Тест:** ловушки `RV-11#1`…`RV-11#8` (`TrapsTest`).
- **Правило детектора:** только статическое (зависит от символов данных), см. ниже.

1. Свёртка регистра. Без флага `u` JS сравнивает символы через одиночный `toUpperCase` и не сводит не-ASCII символ к ASCII. Движок использует `Pattern.CASE_INSENSITIVE | Pattern.UNICODE_CASE`, у которого свёртка шире: `ſ` (U+017F) ≈ `s`, знак Кельвина `K` (U+212A) ≈ `k`, `İ` ≈ `i`, `ı` ≈ `I`, `ß` ≈ `ẞ`. Обычные пары регистра (латиница с диакритикой, кириллица) совпадают с JS.

```
$match("ſ", /s/i)
jsonata-js 2.2.2: undefined
движок:           {"match":"ſ","index":0,"groups":[]}
```

2. Ссылка вперёд: `\2` до того, как группа 2 захвачена, в JS совпадает с пустой строкой, в Java — не совпадает.

```
$match("ab", /(a)\2(b)/)
jsonata-js 2.2.2: {"match":"ab","index":0,"groups":["a","b"]}
движок:           undefined
```

Правило детектора: литерал regex с флагом `i`, где есть `s`, `k`, `i` или `ß` (в шаблоне или ожидаемых данных — `ſ`, `K`, `İ`, `ı`, `ẞ`); обратная ссылка `\N`, стоящая левее открытия группы N.

Случаев test-suite: нет. Ловушки: `RV-11#1`…`RV-11#6` (`compat/traps/review.jsonl`).

## DEV-07. `$toMillis` без смещения — всегда UTC

- **Категория:** DT (пояс), Р2.
- **Причина:** решение владельца по ревью RV-15.
- **Решение:** владелец, 2026-10-25 (ревью RV-15, Р2).
- **Версия движка:** 0.1.0.
- **Меняет результат:** да, на сервере с поясом не UTC.
- **Тест:** `EngineTest` «toMillis without an offset is UTC whatever the JVM time zone (DEV-07, RV-15)».
- **Правило детектора:** см. ниже; проба в разборе даты без смещения — шаг 1.4.

Дату-время ISO без смещения (`2023-11-14T22:13:20`) jsonata-js разбирает через `Date.parse`, то есть как местное время процесса Node: результат зависит от `TZ` машины. Движок всегда читает её как UTC, независимо от часового пояса JVM. При `TZ=UTC` результаты совпадают (в этой среде получены ожидания test-suite).

```
$toMillis("2023-11-14T22:13:20")
jsonata-js 2.2.2, TZ=Europe/Moscow: 1699989200000
jsonata-js 2.2.2, TZ=UTC:           1700000000000
движок (любой пояс):                1700000000000
```

Только дата (`2023-11-14`) и дата-время со смещением или `Z` у эталона тоже не зависят от пояса и совпадают.

Правило детектора: `$toMillis` с одним аргументом, если строка содержит время (`T…`) без `Z` и без смещения `±hh:mm`.

Случаев test-suite: нет (test-suite рассчитан на `TZ=UTC`).

## DEV-08. Конструктор объекта над пустым массивом не меняет этот массив

- **Категория:** DATA (мутация входа).
- **Причина:** решение 8 (вычисление не мутирует данные); найдено дифф-фаззингом (фаза 8).
- **Решение:** владелец, 2026-10-25 (решение 8; фаза 8).
- **Версия движка:** 0.1.0.
- **Меняет результат:** да.
- **Тест:** ловушки `FZ-05#1`, `FZ-05#2` (`TrapsTest`).
- **Правило детектора:** см. ниже; проба — шаг 1.4.

`evaluateGroupExpression` эталона, получив пустой массив, делает `input.push(undefined)` прямо в этот массив, чтобы литерал объекта всё равно построился. Если массив — часть данных (пустой массив во входе, в копии трансформации), он навсегда получает элемент `undefined`. Движок строит объект так же, но массив не трогает.

```
(a{"k":1}; $count(a))                 вход {"a":[]}
jsonata-js 2.2.2: 1   (вход стал {"a":[undefined]})
движок:           0

[[], "x"] ~> |$|{}|
jsonata-js 2.2.2: [[null],"x"]
движок:           [[],"x"]
```

Правило детектора: группировка или конструктор объекта (`path{…}`, `|…|{…}|`), применённые к значению, которое может оказаться пустым массивом данных.

Случаев test-suite: нет.

## DEV-09. Какую ошибку сообщить, если падают несколько значений конструктора

- **Категория:** ERR (порядок ошибок).
- **Причина:** асинхронность эталона — артефакт JS (CLAUDE.md); найдено дифф-фаззингом.
- **Решение:** владелец, 2026-10-25 (решение 3; фаза 8).
- **Версия движка:** 0.1.0.
- **Меняет результат:** только код ошибки, когда падают несколько значений конструктора.
- **Тест:** дифф-фаззинг (`KnownDifferences`); модульный тест — шаг 1.4.
- **Правило детектора:** не нужно.

jsonata-js вычисляет значения конструктора объекта (и элементы конструктора массива) через `Promise.all`: все значения запускаются вместе, и при нескольких ошибках наружу выходит та, что раньше завершилась по числу `await` внутри, а не первая по порядку. Движок вычисляет значения по порядку и сообщает первую ошибку.

```
{"a": ($pad(2.5, null)), "b": (false < $nothing)}
jsonata-js 2.2.2: T2010 (второе значение: в первом лишний блок даёт больше await)
движок:           T0410 (первое значение)
{"a": $pad(2.5, null), "b": (false < $nothing)}
jsonata-js 2.2.2 и движок: T0410
```

Значение без ошибок одинаково; отличается только код ошибки, когда ошибок несколько.

Правило детектора: не нужно (зависит только от того, какая из двух ошибок попадёт в сообщение).

Случаев test-suite: нет.

## DEV-10. Ошибка внутри лямбды сохраняет позицию оператора

- **Категория:** ERR-POS (своя); кандидат P-01.
- **Причина:** отладка (решение 12): позиция указывает на место ошибки, цепочку вызовов даёт стек вызовов (CAP-9, история 2).
- **Решение:** ИТ-лид, 2026-10-25 (решение по P-01…P-03, `docs/plan/decision.md` У3).
- **Версия движка:** 0.1.0.
- **Меняет результат:** только `position` ошибки; код, `token` и значение те же.

jsonata-js записывает на объект лямбды позицию и имя её последнего вызова и затирает позицией вызова позицию любой ошибки из её тела (`applyInner`: `err.position = proc.position || err.position`). Поэтому ошибка указывает на вызов, а при вложенных вызовах — на самый внешний. Движок оставляет позицию ошибки, если она уже есть. Позицию вызова получает только ошибка без своей позиции: проверка сигнатуры лямбды, `D1011` и `D1012` на входе в узел. Имя (`token`) по-прежнему берётся у вызова, если у ошибки его нет.

```
($f := function(){ 1 + "a" }; $f())
jsonata-js 2.2.2: T2002, position 33 (вызов $f()), token "+"
движок:           T2002, position 22 (оператор +), token "+"

($g := function($x){ $x + "a" }; $f := function(){ $g(1) }; $f())
jsonata-js 2.2.2: T2002, position 53 (внешний вызов $f())
движок:           T2002, position 25
```

Случаев test-suite: нет (test-suite не проверяет `position` ошибок вычисления; сверка позиций — шаг 1.2 истории 1).

**Тест:** `DeviationProbeTest` «DEV-10 an error inside a lambda keeps the position of the operator».
**Проба:** `Evaluator.applyInner`, ветка, где эталон заменил бы позицию ошибки позицией вызова, а у ошибки уже есть другая позиция.
**Статическое правило:** определение функции (`function`/`λ`) — «ошибка из её тела укажет на оператор, а не на вызов». Дифф-фаззинг объясняет расхождение позиции этим отличием только при сработавшей пробе.

## DEV-11. `$base64encode`/`$base64decode` в UTF-8

- **Категория:** STR-03 (отчёт по ловушкам jsonata-java); кандидат P-02.
- **Причина:** корректные данные: эталон портит любые символы выше U+007F.
- **Решение:** ИТ-лид, 2026-10-25 (`docs/plan/decision.md` У3).
- **Версия движка:** 0.1.0.
- **Меняет результат:** да, для строк с символами выше U+007F (при кодировании) и для данных с байтами выше 0x7F (при декодировании).

jsonata-js под Node вызывает `Buffer.from(str, 'binary')` и `toString('binary')`: при кодировании от каждого символа UTF-16 остаётся младший байт, при декодировании каждый байт становится символом U+0000–U+00FF. Движок работает так же, как Node с кодировкой `utf8`:
- кодирует байты UTF-8 строки; одиночный суррогат становится U+FFFD;
- декодирует байты как UTF-8 по стандарту WHATWG: каждый максимальный неверный фрагмент даёт U+FFFD;
- разбор самого base64 нестрогий, как у Node: url-safe алфавит, мусор и `=` пропускаются, символ классифицируется по младшему байту.

Совпадает только ASCII. Latin-1 (U+0080–U+00FF) уже отличается: «é» — это один байт `E9` у эталона и два байта `C3 A9` в UTF-8.

```
$base64encode("Привет")
jsonata-js 2.2.2: "H0A4MjVC"            (байты 1F 40 38 32 35 42)
движок:           "0J/RgNC40LLQtdGC"    (UTF-8)

$base64encode("é")      jsonata-js 2.2.2: "6Q=="   движок: "w6k="
$base64decode("w6k=")   jsonata-js 2.2.2: "Ã©"     движок: "é"
$base64decode("6Q==")   jsonata-js 2.2.2: "é"      движок: "\uFFFD" (E9 — не UTF-8)
```

Случаев test-suite: нет. Ловушки `STR-03#1`, `STR-03#2`, `t-str-b64-utf`, `t-str-b64-dec-utf`, `FZ-07#1` допущены в `TrapsTest` со ссылкой на это отличие.

**Тест:** `DeviationProbeTest` «DEV-11 base64 in UTF-8» (ожидания сняты с Node 22, `Buffer` с `utf8`).
**Проба:** `Encoding.base64encode` — в строке есть символ выше U+007F; `Encoding.base64decode` — среди байтов есть байт выше 0x7F.
**Статическое правило:** вызов `$base64encode`/`$base64decode`.

## DEV-12. `undefined` не попадает в последовательности

- **Категория:** UND-SEQ (своя: `undefined` в последовательностях); кандидат P-03 с обоими примерами (Д3).
- **Причина:** предсказуемость результата: «дыры» в последовательностях превращаются в `null` в JSON, а шаг после выбранного элемента конструктора теряет значение.
- **Решение:** ИТ-лид, 2026-10-25 (`docs/plan/decision.md` У3; второй пример исправляется сразу, Д3).
- **Версия движка:** 0.1.0.
- **Меняет результат:** да.

**1. Фильтр не оставляет `undefined`.** Для элемента пути без значения jsonata-js оборачивает `undefined` в `[undefined]` (`evaluateFilter` → `createSequence(undefined)`), и если предикат его пропускает, `undefined` остаётся в результате. В JSON он пишется как `null`. Движок предикат для такого элемента всё равно вычисляет, поэтому его ошибки остаются те же, но сам элемент в результат не кладёт. Так же при раскрытии последовательностей в шаге пути пропускается элемент `undefined`.

```
x.a[true]                 вход {"x":[{"a":1},{"b":2},{"c":3}]}
jsonata-js 2.2.2: [1,null,null]
движок:           1

x.(a ? a : c)[true]       тот же вход
jsonata-js 2.2.2: [1,null,3]
движок:           [1,3]
```

**2. Шаг после конструктора массива с фильтром обходит выбранный элемент.** Если первый шаг пути — конструктор массива с предикатом и предикат выбирает один элемент, шаг схлопывается до этого элемента. Следующий шаг эталон обходит по `.length`: у объекта и числа длины нет, и результат — `undefined`, а строку эталон обходит по символам. Движок оборачивает выбранный элемент в последовательность.

```
[{"a":1},{"a":2}][0].a
jsonata-js 2.2.2: undefined
движок:           1

[5][0].($ + 1)              jsonata-js 2.2.2: undefined        движок: 6
["abc"][0].$uppercase($)    jsonata-js 2.2.2: ["A","B","C"]    движок: "ABC"
```

Не меняются: выбор нескольких элементов (`[…][true].a`), элемент-массив (`[[1,2]][0].($*10)`), скобки (`([…][0]).a` — так можно получить одинаковый результат на обоих движках), путь из одного шага.

Случаев test-suite: нет. Ловушки не затронуты.

**Тест:** `DeviationProbeTest` «DEV-12 undefined does not enter sequences»; `EngineTest` «undefined is not null»; `JsonataJsonTest` (RV-3) проверяет `undefined` внутри массива на `$match(...).groups`.
**Проба:** `Evaluator.filter`, элемент `undefined`, который предикат пропустил бы; раскрытие шага в `Evaluator.step`; `PathNode`, обёртка выбранного элемента конструктора.
**Статическое правило:** путь, где первый шаг — конструктор массива с предикатом и за ним есть шаги; фильтр (не числовой индекс) на шаге, значения которого может не быть у части элементов (имя, переменная, вызов, блок, условие).

## DEV-13. `$eval` не оборачивает ошибки движка и исключения хоста

- **Категория:** ERR-EVAL (своя).
- **Причина:** CAP-9 п. 4: исключение функции хоста доходит до вызывающего с исходной причиной, нигде не подменяется; ошибки движка (`X`: лимиты, отмена, расширения) не превращаются в ошибку разбора чужого выражения.
- **Решение:** утверждённая спека и дизайн (ИТ-лид, 2026-10-25; `docs/plan/design.md` §2.2 «Ошибки», RV-20 критики).
- **Версия движка:** 0.1.0.
- **Меняет результат:** только код ошибки (и тип исключения хоста) внутри `$eval`.

`functionEval` эталона ловит любую ошибку вычисления и бросает `D3121` с её текстом в `value` (ошибку разбора — `D3120`). Движок оборачивает в `D3120`/`D3121` только ошибки с кодами эталона (`S`, `T`, `D`), а ошибку с кодом `X` и исключение функции хоста пропускает как есть. Так же правая часть `and`/`or` не переносит позицию ошибки с кодом `X` на оператор.

```
$eval("$contains('a', /a++/)")
jsonata-js 2.2.2: D3121 (внутри — SyntaxError JS)
движок:           X0003

$eval("$hostFn()")         функция хоста бросает IllegalStateException
jsonata-js 2.2.2: D3121 с текстом ошибки
движок:           то же IllegalStateException

$eval("1 + 'a'")           и движок, и jsonata-js 2.2.2: D3121 (внутри T2002)
```

Случаев test-suite: нет.

**Тест:** `ErrorsTest` «eval wraps reference errors only (DEV-13)», «a host exception reaches the caller unchanged from every higher-order place», «and or keep the place of engine errors».
**Проба:** `$eval`, ветка ошибки с кодом `X` или исключения хоста.
**Статическое правило:** не нужно: отличие видно только на ошибке, и проба показывает её.

## DEV-14. Тексты нарушений JSON Schema — networknt, а не ajv (отличие от ядра SEAF)

- **Категория:** SEAF-SCHEMA (отличие от ядра seaf-archtool-core, не от jsonata-js).
- **Причина:** валидатор JSON Schema в JVM — networknt `json-schema-validator` 3.0.8 (решение ИТ-лида Д1; та же версия, что в `lang-schema` языкового сервера). Своих текстов ajv у него нет, а переводить тексты ajv дословно — поддерживать чужой каталог сообщений.
- **Решение:** ИТ-лид, вариант А (2026-10-25): поведение схем как у ajv ядра, отличаются только тексты (`docs/plan/design.md` §2.3 «JSON Schema», спека CAP-5 п. 8).
- **Версия движка:** 0.1.0.
- **Меняет результат:** поле `message` каждого нарушения и тексты, в которые нарушения входят: `X-MF-PARAMS`/`X-MF-RESULT` функций манифеста (шаг 3.4), список ошибок `$jsonschema` (шаг 3.3), поле `error` у `$tryexecute` над ними.

Что совпадает с ajv 8.20.0 и ajv-formats 2.1.1 в настройках ядра: валидность, ошибка компиляции схемы (строгий режим: неизвестное ключевое слово, неизвестный `format`, `additionalItems` без массива `items`, `if` без `then`/`else`, невалидная схема по метасхеме draft-07, неразрешимый `$ref`, regex, который JS не компилирует), состав нарушений — `instancePath`, `keyword`, `params`. `pattern` — синтаксис regex JS через транслятор движка: с флагом `u` для `params`/`result` функций манифеста и без него для `$jsonschema` (`unicodeRegExp: false` в ядре). Форматы `$jsonschema` — регулярные выражения и проверки ajv-formats (full).

Что отличается:
- `message` — тексты networknt (английские, `Locale.ROOT`, не зависят от локали JVM) или короткие тексты адаптера для ключевых слов, которые он проверяет сам;
- порядок нарушений в списке может отличаться (ajv идёт по группам ключевых слов, networknt — по порядку в схеме); набор тот же;
- `schemaPath` строит networknt, с конформансом не сверяется.

```
$jsonschema({"type": "object", "required": ["b"]})({"a": 1})
ядро (ajv):  [{"instancePath": "", "keyword": "required", "params": {"missingProperty": "b"},
               "message": "must have required property 'b'", ...}]
движок:      [{"instancePath": "", "keyword": "required", "params": {"missingProperty": "b"},
               "message": "required property 'b' not found", ...}]
```

**Тест:** `SchemaConformanceTest` по `compat/seaf/ajv-expected.jsonl` (снимает `compat/node/ajv-expected.mjs` с ajv 8.20.0 и ajv-formats 2.1.1 из npm): 253 схемы, 380+ сравнений, текст не сравнивается.
**Проба:** нет — тексты отличаются всегда, когда есть нарушение.
**Статическое правило:** вызов `$jsonschema` и функция манифеста с `params`/`result` (шаг 3.5).

## Нестабильность эталона (не отличия)

- `$power`: последние биты результата зависят от реализации `Math.pow` в V8. Движок берёт `StrictMath.pow` (fdlibm): на ловушке NUM-11 совпадает с V8, на случайных аргументах расходится в последнем бите примерно в 4–5% случаев. Test-suite не затронут.
- `$now()`, `$millis()`, `$random()`, `$shuffle()` — время и случайность.
