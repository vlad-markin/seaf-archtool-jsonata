# Отличия от jsonata-js 2.2.2

Осознанные отличия движка от эталона (решение 17 в `docs/context.md`): они встроены всегда, переключателя нет. Гейт test-suite — `eval` 1686/1686 за вычетом id случаев, перечисленных здесь. Сейчас ни одно отличие не затрагивает случаи test-suite.

Кандидаты, которые ещё не согласованы, лежат в `docs/proposals.md`; до согласования поведение — как у эталона.

## DEV-01. Трансформация не меняет входной документ

**Причина:** решение 8 (разобранный документ переиспользуется между вычислениями, вычисление не мутирует вход).

jsonata-js меняет найденные шаблоном объекты на месте. Обычно это объекты копии из `$clone`, но шаблон может указать и на исходный документ (`$$`), и тогда эталон меняет вход. Мы применяем обновление и удаление только к объектам копии.

```
($r := $ ~> |$$.a|{"b":99}|; [$r, $$.a.b])      вход {"a":{"b":1}}
jsonata-js 2.2.2: [{"a":{"b":1}}, 99]
движок:           [{"a":{"b":1}}, 1]
```

Случаев test-suite: нет.

## DEV-02. Исчерпание JVM-стека — ошибка `X0002`

**Причина:** решение 18 (свои коды движка с буквой `X`).

Нехвостовая рекурсия, которая не упирается в лимит глубины, в jsonata-js заканчивается `RangeError: Maximum call stack size exceeded` (ошибка JS без кода JSONata). У нас это `JsonataException` с кодом `X0002`: вычисление не роняет поток. Глубина, которую выдерживает стек, у движков разная.

Случаев test-suite: нет.

## DEV-03. Частичное применение нативной функции проверяет сигнатуру

**Причина:** нативный код получает аргументы, уже проверенные и приведённые сигнатурой.

jsonata-js вызывает частично применённую нативную функцию в обход сигнатуры (`applyNativeFunction`). Мы проверяем аргументы по её сигнатуре. Результат расходится только там, где jsonata-js падает с `TypeError` или полагается на нестрогую типизацию JS: например, `$sum(?)(5)` у эталона даёт `TypeError`, у нас — 5.

Случаев test-suite: нет.

## DEV-04. Синтаксис regex, недопустимый в JS, — ошибка `X0003`

**Причина:** решение 18. `java.util.regex` принимает конструкции, которых нет в JS (`a++`, `(?i)`, `(?>...)`). jsonata-js на них падает с `SyntaxError` при вычислении литерала (ошибка JS без кода JSONata). Мы отвергаем такой литерал тоже при вычислении, с кодом `X0003` и позицией литерала.

```
$contains('aa', /a++/)
jsonata-js 2.2.2: SyntaxError: Invalid regular expression: /a++/g: Nothing to repeat
движок:           X0003 Invalid regular expression "a++": Nothing to repeat
```

Случаев test-suite: нет. Ловушки: `RE-01#4`, `RE-01#5` (`compat/traps`).

## DEV-05. Кодовые единицы UTF-16 в regex: ограничение эмуляции

Без флага `u` JS сопоставляет кодовые единицы UTF-16, а `java.util.regex` — кодовые точки. Чтобы повторить JS (эмодзи — две единицы, `.` берёт одну, ловушка RE-07), движок отображает каждый суррогат один к одному в символы частной области U+E000–U+E7FF и в шаблоне, и в строке. Расхождение возможно, только если строка или шаблон содержат настоящие символы U+E000–U+E7FF вместе с суррогатами: например, `$contains("", /[\uD800]/)` у нас `true`, у эталона `false`.

Случаев test-suite: нет.

## Нестабильность эталона (не отличия)

- `$power`: последние биты результата зависят от реализации `Math.pow` в V8. Движок берёт `StrictMath.pow` (fdlibm): на ловушке NUM-11 совпадает с V8, на случайных аргументах расходится в последнем бите примерно в 4–5% случаев. Test-suite не затронут.
- Дата-время ISO без смещения в `$toMillis` jsonata-js читает как местное время процесса Node; движок — как UTC (в этой среде получены ожидания test-suite).
- `$now()`, `$millis()`, `$random()`, `$shuffle()` — время и случайность.
