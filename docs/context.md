# Контекст и решения

Выжимка того, что решено вне этого репо (спека `add-jsonata-cache-driver-contract` в seaf-archtool-specs, ADR `seafteam.adr.jsonata_cache_driver` в модели архитектуры). Облачной сессии этих репо не видно, поэтому здесь — всё, что нужно для фаз 1–5 и чтобы не закрыть дорогу фазам 6–9.

## Почему свой движок

jsonata-js на больших архитектурах медленная (сотни тысяч объектов в манифесте) и не отдаёт управление: вычисление нельзя отменить, ограничить по времени или шагам, нельзя посчитать его стоимость. Существующий порт dashjoin/jsonata-java — построчный перенос JS, его проблемы те же. Его можно смотреть как подсказку для сложных мест (даты, `$formatNumber`, регулярные выражения), но код не копируем: архитектура другая.

В октябре 2026 форк dashjoin оценили всерьёз (публичный репо `vlad-markin/jsonata-java`, ветка `claude/eval-js-2.2.2`, отчёт `compat-eval/REPORT.md`): каталог из 50 расхождений с jsonata-js 2.2.2 и их причины, результаты дифф-фаззинга, прототип отладочного API (ветка `claude/debug-api`). Этот отчёт — готовый список ловушек для нашего движка, читай его перед фазами 4–5. Владелец выбрал свой движок на Kotlin, а не развитие форка (2026-10-25).

## Решения исполнителя по ревью (на подтверждение владельца)

- **Контекст вызова функции (RV-9).** Функция-значение (лямбда, трансформер, частичное применение), созданная в одном вычислении и вызванная в другом (привязки, будущие `manifest.functions`), выполняется под контекстом **вызывающего** вычисления: его лимиты, часы `$now()`/`$millis()`, реестр функций. Переменные берутся из замыкания (лексически). Место последнего вызова лямбды, которое эталон пишет на объект функции для позиции ошибки, хранится в контексте вычисления, а не в лямбде, поэтому одну функцию можно безопасно вызывать из нескольких вычислений одновременно. Так же хранится состояние regex-значения (`lastIndex`, сопоставитель с контрольной точкой вычисления): regex, вышедший из вычисления, можно передавать в другие вычисления, в том числе параллельные (ревью RV2-2).
- **Поток вызова функции хоста не гарантирован (RV2-11).** Глубокое вычисление, а выражение с рекурсивной лямбдой — с самого начала, идёт на потоках сегментов стека движка (`jsonata-stack-segment-N`, `docs/limits.md`). Поэтому `ThreadLocal` хоста (контекст безопасности, MDC, трассировка), установленный в потоке, который вызвал `evaluate`, функции хоста может быть не виден, а два вызова одной функции в одном вычислении могут прийти из разных потоков. Данные хоста передаются через привязки, `EvaluationOptions.attributes` (`CallContext.attribute`) или `CallContext.local`. Блокирующий вызов допустим, прерывание означает отмену, исключение доходит до вызывающего тем же объектом (KDoc `NativeImplementation`).

## Ответы ИТ-лида (2026-10-25)

Спека `docs/plan/SPEC.md`, дизайн `docs/plan/design.md` и решение главного архитектора `docs/plan/decision.md` утверждены.

- **Порядок ключей (ORD-01)** — как у объектов JS: ключи-индексы массива первыми по возрастанию, остальные в порядке вставки (CLAUDE.md, CAP-2 п. 1).
- **Ошибки эталона** исправляются как согласованные отличия, если гейты корпуса и озёр не нашли затронутых выражений; каждое — отдельная запись (CAP-1 п. 5, `docs/compat-policy.md`). Приняты: P-01 → DEV-10, P-02 → DEV-11, P-03 с обоими примерами → DEV-12.
- **Флаг инсталляции** (CAP-16) переключает весь инструмент на движок; отличия действуют ровно при включённом флаге, своего флага у движка нет (решение 17).
- **Отладчик до флага:** можно давать в IDE до включения флага; он работает на JVM-движке и показывает места, где портал на jsonata-js может дать другой результат (по `docs/deviations.md` и правилам детектора).
- **Лимиты:** значения по умолчанию для глубины и последовательностей живут в `jsonata-core`; учёта памяти нет (К5); процессный бюджет сегментов стека — `docs/limits.md`.
