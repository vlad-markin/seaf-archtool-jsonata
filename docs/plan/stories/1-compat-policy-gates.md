## Intent
**Problem:** Правило «максимальная совместимость, компромиссы только с согласия владельца» записано в `docs/context.md` одной строкой. Как предлагать отличие, чем его мерить, где его записывать и по каким гейтам принимать совместимость — не определено. Облачная сессия уже ведёт `docs/proposals.md` (P-01…P-04) и `docs/deviations.md` (DEV-01…09) без обязательных полей: нет категории, решения с датой, версии и теста. Принятые владельцем P-01…P-03 ещё не записаны.
**Approach:** Описать политику (CAP-1) и гейты (CAP-2) в репозитории движка. Закрепить заморозку диалекта тестами (CAP-3). Довести принятые отличия до формата (CAP-1 п. 8). Сделать детектор (выражения, затронутые отличиями; конфликты имён функций манифеста; вызовы `$set`/`$get`) и гейт озёр как CLI `jsonata-tools` — только исходники, без публикации в Maven Central; страницу отличий и документацию флага инсталляции (CAP-15, CAP-16). Само переключение инструмента по флагу CAP-16 делают отдельные задачи зон core и ide.

## Boundaries & Constraints
**Always:** эталон — jsonata-js 2.2.2; каждое расхождение классифицировано; до решения владельца — поведение эталона; храповик только растёт, кроме записей с id отличия; в репозиторий идут только агрегированные числа по корпусу и озёрам.
**Never:** не править `compat/jsonata-js/` и снапшоты ради прохождения теста; не коммитить корпус SEAF, данные озёр и тексты выражений из них; не принимать отличие без решения владельца; не обновлять эталон до версии новее 2.2.2.
