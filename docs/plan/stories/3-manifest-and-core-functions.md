## Intent
**Problem:** Выражения метамодели опираются на функции раздела `functions` и функции ядра, которые сейчас реализованы в Node (`driver.mjs`, `functions.mjs`). Без них корпус SEAF на движке не вычисляется. Ошибки функций манифеста — это текст `Error` без кода и позиции.
**Approach:** Перенести семантику функций манифеста (CAP-5) и функций ядра (CAP-6) в движок на Kotlin. Эквивалентность ядру доказать тестами на эталонных значениях драйвера ядра. Каждая функция получает документацию (через реестр истории 2), структурированные ошибки и кадр в отладчике.

## Boundaries & Constraints
**Always:** семантика ядра `origin/dev` (alias как поле входа, `param<N>`, параметры-лямбды как `$alias`, `callback`/`params` = функция, вход `undefined` без `params`); `$lookup` ядра оформлен как явное переопределение stdlib; `$parsesource` — единственный вызов хоста, блокирующий, с отменой и дедлайном; хранилище `$set`/`$get` живёт одно вычисление, в том числе внутри функций манифеста; функция манифеста с именем stdlib или функции ядра — ошибка загрузки манифеста со списком всех конфликтов; рекурсия функций манифеста до 100 000 уровней проходит; ошибки лимитов не перехватываются `$tryexecute`; JSON Schema — networknt в модуле функций SEAF, поля нарушений как в ядре, тексты `message` — networknt (отличие от ядра); поведение 12 функций описано публично, эталоны привязаны к коммиту ядра.
**Never:** зависимостей в `jsonata-core` ради JSON Schema; изменений в ядре или в схеме `functions`; изменения семантики функций без CAP-1; копирования кода ядра в репозиторий движка; отличий схем от ядра, кроме текстов ошибок: `pattern` — regex JS через транслятор движка, строгий режим ajv (неизвестное ключевое слово или `format` — ошибка схемы).

## Code Map
- Новый модуль `jsonata-seaf` (по дизайну sa-jvm): функции ядра, функции манифеста, валидатор JSON Schema на networknt `json-schema-validator` (зависимость согласована владельцем только для этого модуля), временные лимиты по умолчанию.
- Эталоны функций ядра: синтетические входы, значения, снятые прогоном драйвера ядра, коммит ядра и хэши его файлов; проверка дрейфа; описание поведения в `docs/`.
- Реестр истории 2 — регистрация функций ядра (с признаком переопределения для `lookup`) и функций манифеста с документацией из `title` и `params`.
- Интерфейс хоста для `$parsesource` (загрузка ресурса) и логгера `$log`.
- Эталон поведения (только чтение): `seaf-archtool-core` `src/global/jsonata/driver.mjs:48-356`, `src/global/jsonata/functions.mjs:42-208`, `src/backend/helpers/jsonata/versionsFunc.mjs`.
- Не трогать: `seaf-archtool-core` (переключение ядра на движок — отдельная задача).

## Tasks & Acceptance
**Execution:**
- [ ] Функции манифеста: разбор раздела `functions`, ошибка загрузки при конфликте имён со stdlib и ядром (CAP-7), проверка `params`/`result` по JSON Schema, лямбды, компиляция один раз на версию манифеста, ошибки (CAP-5).
- [ ] Функции ядра: 12 функций и `$self`/`$params`, `$parsesource` через хост, `$log` через логгер хоста, хранилище `$set`/`$get` на одно вычисление (CAP-6).
- [ ] Тесты эквивалентности на эталонных значениях драйвера ядра, привязанных к коммиту ядра; проверка дрейфа; публичное описание поведения 12 функций (TC-11, TC-23).
- [ ] Отличия от ядра — в разделе страницы отличий: `$set`/`$get`, конфликт имён, тексты JSON Schema, лимиты мимо `$tryexecute` (CAP-15 п. 1).
- [ ] Прогон корпуса с функциями ядра в гейте озёр (TC-05).

**Acceptance Criteria:**
- Given манифест с `demo_summ` из документации ядра, when вычисляется `$demo_summ([1,2,3,4,5,15])`, then результат `30` (TC-11).
- Given `$demo_summ([])`, when вычисляется выражение, then структурированная ошибка с id `demo_summ` и нарушением `minItems` (TC-11).
- Given функция с параметром-лямбдой, when её вызывают 1000 раз с разными лямбдами, then `code` компилируется один раз (TC-11).
- Given выражения из TC-23, when они вычисляются движком и драйвером ядра, then результаты равны (TC-23).
