## Intent
**Problem:** Архитектор не видит, где ошибка, какие значения принимали промежуточные выражения и где медленно. Это главная боль пользователей JSONata. У узлов AST движка есть только `position` (конец токена), диапазонов нет. Отладочного API нет.
**Approach:** Отладочный контракт движка (CAP-10) по требованиям части A `debugger-api.md` из оценки порта dashjoin, с закрытием пробелов прототипа (индекс итерации, кадры нативных функций, `$eval` как источник). Трассировка и профиль без интерактивного отладчика (CAP-11). Пороги цены (CAP-12).

## Boundaries & Constraints
**Always:** диапазоны в кодовых единицах UTF-16, строки и колонки с 1; порядок событий — порядок вычисления 2.2.2; отладка включается на вычисление; evaluate в кадре без побочных эффектов; время паузы не идёт в дедлайн; с выключенной отладкой — в пределах порога CAP-12.
**Never:** менять формат `ast()` и `position` ошибок (храповик ast 1686/1686); держать отладочное состояние в глобальных переменных или в окружении выражения; копировать код порта dashjoin; делать DAP-адаптер или UI в этой истории.

## Code Map
- `jsonata-core/.../parser/Parser.kt`, `Tokenizer.kt`, `Ast.kt` — диапазоны узлов (начало первого токена — конец последнего), отдельно от `position`.
- Вычислитель — единая точка вычисления узла: внутренний `DebugHook` (`…/engine/Runtime.kt:190`, `…/engine/Nodes.kt:44-66`) становится публичным контрактом; индекс итерации шага, виртуальные кадры нативных функций; стек JSONata — из кадров движка, не из стека JVM (вычисление может переходить на поток другого сегмента стека).
- Новый пакет отладки в `jsonata-core` — индекс узлов, поиск по позиции, сессия, точки останова, шаги, стек, области, evaluate, профиль и трасса (по дизайну sa-jvm).
- `jsonata-compat` — тест диапазонов по всем выражениям test-suite (TC-14).
- Интеграция с историей 4 — пауза вне дедлайна, terminate как отмена.
- Не трогать: `compat/snapshots/ast/`, сериализацию `ast()` в `CompatEngine.kt` (диапазоны в снапшот не попадают).
