## Intent
**Problem:** Язык растёт функциями архитекторов, а в jsonata-js регистрация функции — это просто привязка имени. Нет документации, нет защиты имён stdlib (2.2.2 молча подменяет `$sum`), а ошибки хоста теряются внутри `$sort`, `$replace`, `$eval`, `and`/`or`. Языковой сервер держит свои таблицы функций, и они уже расходятся с ядром: нет `lookup` и `versions`.
**Approach:** Публичный реестр функций в движке (CAP-4) с защитой имён и отчётом конфликтов (CAP-7). Каталог функций для IDE (CAP-8). Структурированные ошибки без подмены причин (CAP-9).

## Boundaries & Constraints
**Always:** сигнатуры в синтаксисе 2.2.2 и ошибки `T0410`/`T0411`/`T0412`; локальная переменная затеняет функцию (семантика 2.2.2); `undefined` ≠ `null` на границе с функцией; функции блокирующие, без мониторов движка на пути вызова; коды и тексты ошибок 2.2.2 сохраняются.
**Never:** загрузки Kotlin-функций из пакетов и плагинов (только код команды); новых зависимостей в `jsonata-core`; молчаливого переопределения stdlib; подмены или проглатывания исключения функции; исключений JVM наружу; кодов расширений, совпадающих с кодами 2.2.2.

## Code Map
- `jsonata-core/src/main/kotlin/su/seaf/archtool/jsonata/` — реестр функций и API регистрации (пакет по дизайну sa-jvm), `explicitApi`.
- `jsonata-core/.../parser/Signature.kt` — разбор сигнатур уже есть, переиспользовать для проверки аргументов.
- Вычислитель фазы 4 — места вызова функций и HOF: проброс исключений без подмены; `$eval` (`…/engine/StandardLibrary.kt:759-777`) оборачивает только ошибки с кодами эталона.
- stdlib фазы 5 — описания и примеры для 65 функций (свои краткие тексты; формат с ключом языка, наполнение сейчас на русском).
- `jsonata-compat` — каталог в JSON для сверки (опционально).
- Не трогать: AST-формат `ast()`, коды ошибок 2.2.2. Языковой сервер в этой истории не меняется.

## Tasks & Acceptance
**Execution:**
- [ ] Реестр: регистрация с сигнатурой и документацией, области «движок» и «вычисление», проверка имени, дубликаты (CAP-4).
- [ ] Защита stdlib, признак переопределения, отчёт конфликтов (CAP-7).
- [ ] Каталог функций и сериализация в JSON; описания stdlib (CAP-8).
- [ ] Структурированная ошибка: код, `position`, диапазон, `token`, `value`, стек кадров, id функции; пространство кодов расширений (CAP-9).
- [ ] Тесты TC-09, TC-10, TC-24, TC-25, TC-26.

**Acceptance Criteria:**
- Given нативная функция с сигнатурой `<s-:s>`, when вызывается `$upper2(1)`, then ошибка `T0410` с позицией вызова (TC-09).
- Given регистрация `sum` без признака переопределения, when движок собирает реестр, then ошибка регистрации с именем `sum` (TC-24).
- Given функция бросает исключение в компараторе `$sort`, when вычисляется выражение, then вызывающий получает ошибку с исходной причиной (TC-26).
- Given stdlib, функции ядра, нативная и функция манифеста, when выгружается каталог, then 78 записей с непустыми описаниями и сигнатурами (TC-25).
- Given 10 тыс. вычислений на виртуальных потоках с блокирующей функцией, when включён JFR, then 0 событий `jdk.VirtualThreadPinned` (TC-10).
